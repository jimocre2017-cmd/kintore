# GAS（バックエンド）

Apps Script プロジェクトにある `Code.gs` の控えと、AIトレーナー用の `AiTrainer.gs`、有酸素用の `Cardio.gs` です。
アプリ（このリポジトリの index.html など）は GitHub Pages、データ処理は Apps Script で動いています。

## AIトレーナーの導入手順

1. Apps Script エディタで `Code.gs` を、このフォルダの `Code.gs` の内容に置き換える
   （変更点は `doPost` の `fns` に `aiConsult` / `aiApplyProgram` / `aiDeleteProgram` の3行を足しただけ）
2. 「＋」→「スクリプト」で `AiTrainer` というファイルを作り、`AiTrainer.gs` の内容を貼り付ける
3. 左の ⚙「プロジェクトの設定」→「スクリプト プロパティ」に追加
   - `GEMINI_API_KEY` … Gemini の API キー
   - `GEMINI_MODEL` … 任意。空なら使える Flash 系モデルを自動で選ぶ（例：特定のモデルに固定したいときだけ設定）
4. エディタで関数 `aiTest` を選んで実行 → 初回は外部通信の許可を求められるので承認。
   実行ログに「モデル：… / 応答：…接続OK…」と出れば成功
5. 「デプロイ」→「デプロイを管理」→ アプリ版用（全員公開）のデプロイを編集し、
   バージョンを「新バージョン」にしてデプロイ（URLは変わりません）

## 注意

- API キーはスクリプトプロパティにだけ置く。このリポジトリは公開なので、コードや HTML に書かない
- AIが作ったプログラムは「タグ設定」シートに `AI` で始まるタグ名で入り、対象の種目マスタT列（タグ）にも同じタグが付く
- 相談の内容と提案は「AI提案履歴」シートに残る
- トレーニング環境（器具）の説明は `AiTrainer.gs` 冒頭の `AI_PROFILE` を書き換える

## 有酸素（ウォーキング・ランニング）の導入手順

1. Apps Script エディタで `Code.gs` を、このフォルダの `Code.gs` の内容に置き換える
   （変更点は `doPost` の `fns` に `cardioGet` / `cardioRoute` を足したことと、`syncOps` に `cardio…` の操作を足したことだけ）
2. 「＋」→「スクリプト」で `Cardio` というファイルを作り、`Cardio.gs` の内容を貼り付ける
3. `AiTrainer.gs` も、このフォルダの内容に置き換える（有酸素の要約をAIトレーナーに渡す変更）
4. エディタで関数 `cardioTest` を選んで実行 → 初回は権限の承認を求められるので承認。
   実行ログに「記録数: 1 …」「テスト記録を削除しました」と出れば成功。スプレッドシートに
   `有酸素ログ` / `コース` / `地点` の3シートが自動で作られます
5. 「デプロイ」→「デプロイを管理」→ アプリ版用（全員公開）のデプロイを編集し、
   バージョンを「新バージョン」にしてデプロイ（URLは変わりません）
6. アプリ（GitHub Pages）を更新したあと、筋トレ記録の画面右上「有酸素 →」から開く

## 消費カロリー（筋トレ＋有酸素の合計と内訳）

記録画面の「消費 kcal」と分析画面の「消費カロリー」カードに、筋トレと有酸素を合算した合計と、それぞれの内訳を出します。

【反映手順】`Code.gs` と `Cardio.gs` を差し替えて保存 → 新バージョンでデプロイ。アプリ（GitHub Pages）を更新して開き直す。設定シートに `kcal_ウォーキング既定時速` / `kcal_ランニング既定時速` の2行が初回の読み込みで自動追加されます。

- 筋トレ：従来どおり（動作と休憩のMETs法。`kcal_動作MET` など）
- 有酸素：`kcal ＝ MET × 体重(kg) × 時間(h)`。MET は平均時速から決める（Compendium of Physical Activities の代表値を時速の間で線形補間。ウォーキング 4.8km/h→3.5、6.4km/h→5.0、ランニング 8.0km/h→8.3、11.3km/h→11.0 など）。表は `Cardio.gs` の `CARDIO_MET` と `cardio-lib.js` の `MET`（同じ値を両方に置く。`node test/cardio-kcal.test.js` が一致を確認）
- 距離か時間が欠けた記録：時間なし→距離÷既定時速、距離なし→既定時速で補う。どちらも無い記録は 0kcal
- 体重：筋トレと同じ（体組成の最新の体重、無ければ `kcal_既定体重kg`）。1回ごとに四捨五入して合計する
- MET 法は安静時の消費を含む「総消費」。筋トレ側も同じ考え方なので、そのまま足しています
- 返り値：`summarizeDay_`（記録画面の本日分）と `getAnalytics` の `total.cur/prev` に `kcal`（筋トレ分・従来どおり）、`kcalStrength`、`kcalCardio`、`kcalTotal` を追加。推移（`trend`）と日計（`daily`）には `kcalS` / `kcalC` / `kcal`（合計）、日表示には `cardio`（1回ごとの消費kcal付き）
- Cardio.gs が無い・読めないときは有酸素分を 0 として筋トレ側を止めません

## 有酸素のデータ

- 1回の運動＝`有酸素ログ`の1行。ルートは「エンコード済みポリライン」（座標列を短い文字列にしたもの）で最後の列に入る
- 日付・開始・終了の列は文字列書式（シートが時刻や日付に自動変換しないため）。手で直す時もこのままにする
- `コース`（GPSで記録したルートを名前を付けて登録）と `地点`（自宅など）は、手動入力でルートを選ぶために使う
- 記録・編集・削除は ID で上書き/削除するので、オフライン中の操作を何度送り直しても二重登録にならない

## 食事のデータ

- シート「食事ログ」：1食1行（IDで上書き）。日付・時刻・区分・内容・kcal・たんぱく質・脂質・炭水化物・内訳・見積もりメモ。
- 見積もりは Gemini による概算。画面で数値を直してから保存する。圏外のときは数値を直接入れて保存できる（AIの見積もりはオンラインのみ）。

- AIトレーナーには、直近7日の1日ごとの合計と平均、今日の合計、目標を渡し、体組成の試算（たんぱく質量・ペース別の到達月数）と突き合わせて助言させる。

## 食事の品目（覚えた内容）

- シート「食事品目」：名前・内容・kcal・たんぱく質・脂質・炭水化物・内訳（1回分）。初回に自動で作られる。
- 食事の入力画面で「この内容を品目として覚える」に名前を入れると登録される。次から名前をタップするだけで入力でき、倍率（半分・2杯など）も指定できる。
- 食事の内容に品目の名前を書いてAIで見積もると、AIは登録済みの栄養をそのまま使う（推測し直さない）。

### 体組成：1日に複数回の測定とタイミング

- 1測定＝1行（シート「体組成ログ」の列：…登録日時, ID, 時刻, タイミング）。朝・昼・晩など何回でも記録でき、グラフ・比較・試算・AI分析は **日ごとの平均** で見ます。
- 測定には「起床後・午前中・日中・午後・夜・就寝前・食事前・食事後・排便前・排便後・運動前・運動後・入浴前後・水分補給前後」を複数付けられます。画面の「集計の条件」で条件を選ぶと、その条件の測定だけで集計します（例：起床後・排便後だけの推移）。
- 旧版の「1日1件」の行はそのまま使えます（IDなしの行は `L日付` のIDとして扱い、列は初回の保存時に自動で追加）。
- AIトレーナーには、日平均・その日の測定一覧（時刻・タイミング付き）・条件ごとの直近28日の平均を渡します。
- 反映手順：Code.gs / Body.gs / AiTrainer.gs を差し替えて保存し、新バージョンでデプロイします。

## 体つき写真（前・横・後ろ）

- 画面：`photo.html`（体組成画面の「写真」から開く）。1回の撮影で前・横・後ろの最大3枚を保存し、向きごとの一覧、同じ向きの過去（1週間前・1か月前・3か月前・最初）との比較、任意の2枚の比較、並べて表示／スライダー、体組成（日平均）の差、AIの所見を使えます。
- 保存先：Googleドライブの専用フォルダ「筋トレトラッカー_体つき写真」（自分だけが見られる非公開。初回の保存時に自動で作られます）。スプレッドシート「体つき写真」には日付・時刻・向き・ファイルIDだけを書きます。
- 写真は端末側で縮小（長辺1280px・サムネイル360px）してJPEGにし直してから送ります。位置情報などのメタデータは含まれません。
- 保存・削除・AI所見はオンラインの時だけできます。一覧とサムネイルは端末にも控えるので、オフラインでも見られます。
- 導入手順：`Photo.gs` を新しいファイルとして追加し、`Code.gs` と `AiTrainer.gs` を差し替えて保存します。エディタで `photoTest` を1回実行して Google ドライブへのアクセスを承認し（初回のみ）、新バージョンでデプロイしてください。
- `photoTest`：テスト写真を保存→取得→削除して、フォルダとシートが使えるか確かめます。

### 写真の自動取り込み（PhotoAuto.gs）

- Googleドライブの `body_pictures` に写真（スマホのHEICのままでOK）を入れるだけで、15分ごとに自動で取り込みます。撮影日時が近い写真を1セット（最大3枚）にまとめ、Gemini が前・横・後ろを判定して、上の体つき写真（`photoSave`）に登録します。
- 登録できた元ファイルは `body_pictures/取込済み` へ移動。向きが判定できない・体の写真でない・同じ向きが重複するものは `body_pictures/要確認` へ移動し、登録しません（誤った向きで記録しないため）。
- ファイル名（`IMG_20261109_013817.heic` など）から撮影日時を読みます。読めないときはアップロード日時で代用します。
- 導入手順：`PhotoAuto.gs` を新しいファイルとして追加し、`Code.gs` を差し替えて保存 → エディタで `photoAutoSetup` を1回実行（権限の承認・15分トリガー作成・初回取り込み）→ 新バージョンでデプロイ。止めるときは `photoAutoStop`。
- `test/photo-auto.test.js`：ファイル名の読み取り・セット分け・向き判定の検証（`node test/photo-auto.test.js`）。

## 減量計画（目標体脂肪率に対する日・週・月のずれ、次週のカロリー調整）

画面：`plan.html`（体組成・食事の画面の「減量計画」から開く）。計算は `plan-lib.js`、画面は `plan-page.js`。

### 導入手順

1. Apps Script のエディタで `PlanLib.gs`（新規）と `Plan.gs`（新規）を作り、このフォルダの内容を貼り付ける。
2. `Code.gs` と `Meal.gs` を最新の内容に置き換える（変更点は、`Code.gs` の `doPost` の `fns` に `planGet` / `planSet` / `planAdvise` / `planApply` を足したことと、`Meal.gs` の `mealGoals_` / `mealSetGoals` に「来週から採用した目標カロリー」の予約処理を足したこと）。
3. 「デプロイ」→「デプロイを管理」→ 既存のデプロイの鉛筆 → 新バージョン → デプロイ。
4. アプリ（GitHub Pages）を更新したあと、体組成または食事の画面右上「減量計画」から開き、「計画を設定する」で目標の体脂肪率・開始日・週あたりの減量を決める。

`PlanLib.gs` は `plan-lib.js` のコピーです。`plan-lib.js` を直したら `node tools/sync-planlib.js` で同期します（`node test/plan-lib.test.js` が一致も確認します）。

### 考え方

- 基準線：開始日からの7日間に測った日の日平均（測った日だけで平均）。3日未満の間は「暫定」。7日が過ぎると固定。測る時刻・条件は問わない（1日に何回でも日平均）。
- 計画ライン：基準の脂肪量から、除脂肪量を維持したまま目標の体脂肪率になる脂肪量まで、週あたり一定のペースで減らす（脂肪1kg=7200kcal）。期限を入れた場合はペースを逆算し、体重の1%/週を超えると警告。
- ずれ：日（直近14日）・週（月曜はじまり）・月で、実績と計画を比べる。日々の体脂肪率は±1%ほど動くので、判断は週の平均。
- 食事：3食以上、または1200kcal以上を記録した日を「記録が揃った日」とみなし、平均や目標差に使う。今週の予算（目標×7）と残りも出す。
- 消費カロリー：体組成が10日分以上たまり、食事の記録が揃った日が7割以上ある間は「摂取 − 脂肪量の変化×7200」で実測する。それまでは基礎代謝×活動係数（初期値1.55）で推定する。
- 次週の調整（`adjust`）：記録が足りない週（食事の記録が揃った日が直近7日で5日未満、または体組成が3日未満）は目標を変えない。足りていれば「消費 − 計画の赤字」を目標とし、1週間に動かす幅は±200kcalまで、50kcal未満の差は据え置き。下限は基礎代謝（最低1200kcal）。
- AI（Gemini）は、確定した数値（`adjust`）を文章にするだけで、数値の変更や再計算はしない。記録不足の週は Gemini を呼ばず、固定の案内を返す。

### データ

- シート「減量調整履歴」（初回に自動で作られる）：作成日時・対象週（月曜）・状態・提案kcal・前回の目標・採用・採用kcal・根拠（JSON）・助言（JSON）。「採用」が「はい」の行が、その週からの1日の目標カロリーになる（過去の週のずれの計算にも使う）。
- スクリプトのプロパティ：`BODY_GOAL_FAT`（目標の体脂肪率・体組成と共通）、`PLAN_START`、`PLAN_WEEKLY_LOSS`、`PLAN_DEADLINE`、`PLAN_ACTIVITY`、`MEAL_GOAL_KCAL`（採用で更新）、`MEAL_GOAL_KCAL_NEXT`（来週から採用した目標の予約。その日が来ると `MEAL_GOAL_KCAL` に移る）。

### テスト

- `node test/plan-lib.test.js`：計算ロジック（実データ3日分と、真の消費カロリーが分かっている合成データ）。
- `node test/plan-gas.test.js`：Apps Script 側を、シート・プロパティ・Gemini を偽物にして動かす確認。


## YKトレーニング（山本KID化計画）

メイン画面の最上部に「YKトレーニング」カードが出ます。胸・脚・背中・肩僧帽筋・腹の充足度（直近7日のセット数÷目標）、
右肩の状態（問題なし／違和感／痛い）、「今日のYK推奨セッション」ボタン、AIの解説があります。

### 導入手順

1. Apps Script のエディタで `Yk.gs`（新規）を作り、このフォルダの内容を貼り付ける。
2. `Code.gs` を最新の内容に置き換える（変更点：設定の既定値に `YK_` の9行、`getInitData` に `ykHist`、`doPost` の `fns` に `ykAdvise` / `ykSetPhase`）。
3. 関数 `ykTest` を実行して、テンプレートの種目IDが種目マスタにあるか確認する（無いIDは実行ログに出る）。
4. （任意）関数 `ykInstallTemplate` を1回実行すると、固定テンプレート `#YKトレーニング` がタグ設定シートと種目のタグに作られる。
5. 「デプロイ」→「デプロイを管理」→ 新バージョンでデプロイ。アプリ（GitHub Pages）を更新して開き直す。

### 考え方

- 今日のメニューは `yk-lib.js` がルールで決める（端末側・オフラインOK）。AI（Gemini）は解説とフェーズ助言だけで、種目・セット数・重さは変えない。
- 不足度＝優先度×(目標−直近7日の消化)/目標。上位2部位を主働筋にする（胸・脚は優先度1.5、腹0.9、他1.0）。目標の1.25倍を超えた部位と、前回から間隔が短い部位（胸・脚は2日、他は1日）は外す。
- セットは「メイン=1、付随部位=0.5」で数える（同じ区分に重なる時は大きい方）。肩インナー（E009・E014）は週のセット数に数えない。
- 最後のトレーニングから `YK_ブランク日数`（既定3）日以上空いたら、脚・胸・背中・体幹を各2セット・重さ1段階下げた「YKリブート」。直近7日以内に復帰メニューをやっていれば通常に戻す。
- 肩保護：メニューの先頭に必ず肩インナーを入れる（プレス系が入る時は2セット）。肩が「違和感」ならインクライン・オーバーハンドのプルアップを、「痛い」ならプレス系・プルアップ系を外す。
- 重さ・回数：前回の記録から、回数の上限に届いたら重さ+1刻み、上限kgなら回数を伸ばす。
- 絞り期→増量期：設定 `YK_フェーズ`（0＝絞り期／1＝増量期）。直近4週のうち胸・脚が目標の9割以上の週が3つ以上で「準備OK」になり、AIが体組成を見て移行を助言する（切り替えは本人がボタンで決める）。増量期は目標セット数が `YK_増量期倍率`（既定1.15）倍になる。
- 設定シートの `YK_` で始まる行で、目標セット数・ブランク日数・上限時間を変えられる。

### 履歴の渡し方

- `getInitData` の `ykHist`＝今日より前の直近35日の `{d:日付, e:種目ID, n:セット数}`。今日の分は端末の `todaySets`（送信待ちも含む）を使う。
- テスト：`node test/yk-lib.test.js`
