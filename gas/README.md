# GAS（バックエンド）

Apps Script プロジェクトにある `Code.gs` の控えと、AIトレーナー用の `AiTrainer.gs`、有酸素用の `Cardio.gs` です。
アプリ（このリポジトリの index.html など）は GitHub Pages、データ処理は Apps Script で動いています。

## AIトレーナーの導入手順

1. Apps Script エディタで `Code.gs` を、このフォルダの `Code.gs` の内容に置き換える
   （変更点は `doPost` の `fns` に `aiConsult` / `aiApplyProgram` / `aiDeleteProgram` の3行を足しただけ）
2. 「＋」→「スクリプト」で `AiTrainer` というファイルを作り、`AiTrainer.gs` の内容を貼り付ける
3. 左の ⚙「プロジェクトの設定」→「スクリプト プロパティ」に追加
   - `GEMINI_API_KEY` … Gemini の API キー
   - `GEMINI_MODEL` … 任意。空なら使える Flash 系モデルを自動で選ぶ（例：特定のモデルに固定したいときだけ設定）
4. エディタで関数 `aiTest` を選んで実行 → 初回は外部通信の許可を求められるので承認。
   実行ログに「モデル：… / 応答：…接続OK…」と出れば成功
5. 「デプロイ」→「デプロイを管理」→ アプリ版用（全員公開）のデプロイを編集し、
   バージョンを「新バージョン」にしてデプロイ（URLは変わりません）

## 注意

- API キーはスクリプトプロパティにだけ置く。このリポジトリは公開なので、コードや HTML に書かない
- AIが作ったプログラムは「タグ設定」シートに `AI` で始まるタグ名で入り、対象の種目マスタT列（タグ）にも同じタグが付く
- 相談の内容と提案は「AI提案履歴」シートに残る
- トレーニング環境（器具）の説明は `AiTrainer.gs` 冒頭の `AI_PROFILE` を書き換える

## 有酸素（ウォーキング・ランニング）の導入手順

1. Apps Script エディタで `Code.gs` を、このフォルダの `Code.gs` の内容に置き換える
   （変更点は `doPost` の `fns` に `cardioGet` / `cardioRoute` を足したことと、`syncOps` に `cardio…` の操作を足したことだけ）
2. 「＋」→「スクリプト」で `Cardio` というファイルを作り、`Cardio.gs` の内容を貼り付ける
3. `AiTrainer.gs` も、このフォルダの内容に置き換える（有酸素の要約をAIトレーナーに渡す変更）
4. エディタで関数 `cardioTest` を選んで実行 → 初回は権限の承認を求められるので承認。
   実行ログに「記録数: 1 …」「テスト記録を削除しました」と出れば成功。スプレッドシートに
   `有酸素ログ` / `コース` / `地点` の3シートが自動で作られます
5. 「デプロイ」→「デプロイを管理」→ アプリ版用（全員公開）のデプロイを編集し、
   バージョンを「新バージョン」にしてデプロイ（URLは変わりません）
6. アプリ（GitHub Pages）を更新したあと、筋トレ記録の画面右上「有酸素 →」から開く

## 有酸素のデータ

- 1回の運動＝`有酸素ログ`の1行。ルートは「エンコード済みポリライン」（座標列を短い文字列にしたもの）で最後の列に入る
- 日付・開始・終了の列は文字列書式（シートが時刻や日付に自動変換しないため）。手で直す時もこのままにする
- `コース`（GPSで記録したルートを名前を付けて登録）と `地点`（自宅など）は、手動入力でルートを選ぶために使う
- 記録・編集・削除は ID で上書き/削除するので、オフライン中の操作を何度送り直しても二重登録にならない

## 体組成の導入手順

1. Apps Script のエディタで `Body.gs` を新規追加し、このリポジトリの `gas/Body.gs` の内容を貼り付ける。
2. `Code.gs` と `AiTrainer.gs` を最新の内容に置き換えて保存する。
3. 関数 `bodyTest` を1回実行して権限を許可する（シート「体組成ログ」が作られ、テスト記録は自動で削除される）。
4. デプロイ → デプロイを管理 → 既存のデプロイの鉛筆 → 新バージョン → デプロイ。

## 体組成のデータ

- シート「体組成ログ」：1日1件（日付がID。同じ日に保存し直すと上書き）。体重・体脂肪率・骨格筋率・BMI・基礎代謝・内臓脂肪レベル・身長・備考。
- 目標の体脂肪率はスクリプトのプロパティ `BODY_GOAL_FAT` に保存（アプリの「目標を設定」から変更）。
- AIトレーナーには、除脂肪体重・目標体重・減らす脂肪量・有酸素の実績にもとづくペース別の到達月数を計算済みの数値で渡す（AIは計算し直さない）。

## 食事の導入手順

1. Apps Script のエディタで `Meal.gs` を新規追加し、このリポジトリの `gas/Meal.gs` の内容を貼り付ける。
2. `Code.gs` と `AiTrainer.gs` を最新の内容に置き換えて保存する。
3. 関数 `mealTest` を1回実行して権限を許可する（シート「食事ログ」が作られ、テスト記録は自動で削除される）。
4. 関数 `mealEstimateTest` を実行し、実行ログにAIの見積もりが出ることを確認する（AIトレーナーと同じ `GEMINI_API_KEY` を使う）。
5. デプロイ → デプロイを管理 → 既存のデプロイの鉛筆 → 新バージョン → デプロイ。

## 食事のデータ

- シート「食事ログ」：1食1行（IDで上書き）。日付・時刻・区分・内容・kcal・たんぱく質・脂質・炭水化物・内訳・見積もりメモ。
- 見積もりは Gemini による概算。画面で数値を直してから保存する。圏外のときは数値を直接入れて保存できる（AIの見積もりはオンラインのみ）。
- 1日の目標（kcal・たんぱく質・脂質）はスクリプトのプロパティ `MEAL_GOAL_KCAL` `MEAL_GOAL_P` `MEAL_GOAL_F` に保存。
- AIトレーナーには、直近7日の1日ごとの合計と平均、今日の合計、目標を渡し、体組成の試算（たんぱく質量・ペース別の到達月数）と突き合わせて助言させる。

## 食事の品目（覚えた内容）

- シート「食事品目」：名前・内容・kcal・たんぱく質・脂質・炭水化物・内訳（1回分）。初回に自動で作られる。
- 食事の入力画面で「この内容を品目として覚える」に名前を入れると登録される。次から名前をタップするだけで入力でき、倍率（半分・2杯など）も指定できる。
- 食事の内容に品目の名前を書いてAIで見積もると、AIは登録済みの栄養をそのまま使う（推測し直さない）。

### 体組成：1日に複数回の測定とタイミング

- 1測定＝1行（シート「体組成ログ」の列：…登録日時, ID, 時刻, タイミング）。朝・昼・晩など何回でも記録でき、グラフ・比較・試算・AI分析は **日ごとの平均** で見ます。
- 測定には「起床後・午前中・日中・午後・夜・就寝前・食事前・食事後・排便前・排便後・運動前・運動後・入浴前後・水分補給前後」を複数付けられます。画面の「集計の条件」で条件を選ぶと、その条件の測定だけで集計します（例：起床後・排便後だけの推移）。
- 旧版の「1日1件」の行はそのまま使えます（IDなしの行は `L日付` のIDとして扱い、列は初回の保存時に自動で追加）。
- AIトレーナーには、日平均・その日の測定一覧（時刻・タイミング付き）・条件ごとの直近28日の平均を渡します。
- 反映手順：Code.gs / Body.gs / AiTrainer.gs を差し替えて保存し、新バージョンでデプロイします。
